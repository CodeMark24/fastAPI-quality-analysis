METHODOLOGICAL DECISIONS
1. FastAPI was retained as the selected project after checking the codebase size against the assignment requirement.
2. Ten releases were selected to examine changes over time.
3. The same SonarQube environment, scanner version, quality profile and source scope were used.
4. The fastapi package was analysed rather than the entire repository.
5. Production code was included in the analysis.
6. Bugs, vulnerabilities and code smells were examined.
7. The default Sonar way quality profile was retained.
8. Public files were identified using interfaces documented in the official FastAPI API reference.
9. Files not implementing documented public interfaces were classified as internal.
10. RQ4 used the 20 files common to all ten releases to ensure a consistent comparison.
11. RQ5 inspected all three bugs reported in release 0.162.4 because the requested sample of 20 was unavailable.

LIMITATIONS AND FLAGGED ISSUES
1. The latest release contained only three detected bugs, rather than the 20 required for the intended RQ5 sample.
2. All three latest-release bugs were inspected, and the sample-size deviation must be disclosed.
3. RQ4 was calculated at file level, not class level.
4. RQ4 was restricted to the 20 files common to all ten releases.
5. SonarQube findings do not represent every possible software defect.
6. Zero vulnerabilities and hotspots do not prove the absence of security weaknesses.
7. No coverage report was imported; the reported 0% coverage must not be interpreted as proof that no tests exist.
8. Technical debt ratios were displayed rounded to one decimal place.
9. Remediation effort summed across releases represents scan observations, not unique project debt.
10. The related Eclipse studies must be verified before making numerical comparisons.

REPRODUCIBILITY
The package contains exported SonarQube JSON data, CSV datasets, analysis scripts, charts and documentation.
The ten releases were analysed as separate SonarQube projects.
Project keys and names were changed for each release while the analysis settings were kept consistent.

CREDENTIALS
No SonarQube tokens, passwords or private credentials should be included in this package.
